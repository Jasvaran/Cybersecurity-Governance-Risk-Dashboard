# Cybersecurity Governance & Risk Dashboard

## Overview

This project simulates a basic cybersecurity governance, risk, and compliance (GRC) workflow for a fictional organization preparing to strengthen its information security program.

The goal of the project is to practice identifying cybersecurity risks, evaluating likelihood and business impact, documenting security controls, selecting risk treatments, tracking control evidence, and presenting risk information through an executive-level dashboard.

The project was built in Microsoft Excel and is intended as a hands-on introduction to concepts commonly used in cybersecurity governance and ISO 27001 readiness efforts.

## Project Components

### Risk Register

The Risk Register tracks identified cybersecurity risks and includes:

- Asset or business process affected
- Risk description
- Likelihood score
- Impact score
- Calculated risk score
- Risk severity
- Existing security controls
- Risk treatment strategy
- Risk owner
- Remediation status

Risk scores are calculated using:

**Risk Score = Likelihood × Impact**

The current scoring model classifies risks as:

- **Low:** 1–7
- **Medium:** 8–14
- **High:** 15–25

## Risk Treatment

The project uses common risk treatment strategies:

- **Mitigate** — implement or strengthen controls to reduce the risk
- **Accept** — acknowledge the risk and determine that no additional action is currently required
- **Avoid** — discontinue the activity that creates the risk
- **Transfer** — shift part of the risk through contractual, insurance, or third-party mechanisms

## Control Evidence Tracker

The Control Evidence Tracker simulates the process of collecting documentation that demonstrates whether security controls have been implemented.

Examples of evidence include:

- MFA configuration records
- Patch compliance reports
- Security awareness training records
- Backup and recovery test results
- User access review records
- Vendor security assessments

Each evidence request includes an owner and status so outstanding items can be followed through to completion.

## Executive Dashboard

The Executive Dashboard summarizes governance information from the risk register and evidence tracker.

Current metrics include:

- Total identified risks
- Number of high-risk items
- Open or in-progress risks
- Outstanding security-control evidence
- Distribution of risks by severity

The dashboard is designed to demonstrate how detailed cybersecurity information can be converted into concise reporting for management and other stakeholders.

## Example Risk

One example risk included in the project involves employee laptops being exposed to malware.

- **Asset:** Employee Laptops
- **Risk:** Malware infection could disrupt operations or expose company data
- **Likelihood:** 4
- **Impact:** 4
- **Risk Score:** 16
- **Risk Level:** High
- **Existing Controls:** Endpoint protection and patch management
- **Treatment:** Mitigate
- **Owner:** IT Security

This demonstrates the process of moving from risk identification to assessment, treatment, ownership, and remediation tracking.

## ISO 27001 Context

This project is not an ISO 27001 certification assessment or implementation.

It was created as a learning project to develop familiarity with governance concepts that can support an Information Security Management System (ISMS), including risk assessment, risk treatment, security controls, evidence collection, ownership, and continual tracking.
